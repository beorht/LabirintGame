# MazeGame — архитектура проекта (реконструкция)

> **Источник данных.** В директории `D:\Projects\MazeGame` присутствует только собранный
> билд (`maze_game.exe` + рантайм Qt6/MinGW + `config.txt`), исходный код (`maze.cpp`,
> `.ui`, `.pro`/`CMakeLists.txt`) отсутствует. Документ восстановлен путём анализа
> de-mangled C++/Qt-символов и текстовых строк внутри `maze_game.exe`. Пункты, отмеченные
> **[инференция]**, — это обоснованная гипотеза по бинарнику, а не факт из кода; при
> переносе их нужно спроектировать заново, а не копировать «как есть».

Цель документа — описать архитектуру на уровне компонентов/ответственностей так, чтобы её
можно было реализовать в любой другой кодовой базе/языке/UI-фреймворке (не привязываясь
к Qt).

---

## 1. Обзор

Настольное приложение "Maze Game": окно с сеткой-лабиринтом, кнопками управления и счётчиками
прогресса. Параметры лабиринта (размер клетки, высота, ширина) задаются во внешнем
конфиг-файле. Оригинал написан на C++17 + Qt6 Widgets (QMainWindow/QWidget, MinGW-w64,
Qt 6.11).

Три логических слоя:

1. **Config layer** — чтение и валидация параметров лабиринта.
2. **Domain/Model layer** — сама сетка лабиринта: генерация стен, положение "визора"
   (текущей позиции), логика перемещения, условие победы.
3. **UI layer** — главное окно, кнопки, статус-бар, диалоги, отрисовка, таймер анимации.

---

## 2. Конфигурация

Файл `config.txt`, простой `key = value` построчно:

```
size_of_cell = 20
height = 4
width = 4
```

| Ключ | Тип | Смысл |
|---|---|---|
| `size_of_cell` | int | размер одной клетки в пикселях (для отрисовки) |
| `height` | unsigned int | высота лабиринта в клетках |
| `width` | unsigned int | ширина лабиринта в клетках |

При переносе: держать парсинг конфига отдельным от домена — модель лабиринта должна
принимать уже провалидированные `height`/`width`/`cellSize`, не знать о формате файла.

**Валидация.** В бинаре есть отдельный класс исключений с сообщением (строковый конструктор)
и диалоговые тексты `"Warning!"`, `"try again"`, `"Failure"` — т.е. невалидный конфиг
(например, 0 или отрицательные размеры) не приводит к падению, а показывает пользователю
диалог и просит поправить файл. Это стоит сохранить как паттерн: **валидация конфига бросает
доменное исключение с человекочитаемым текстом → UI ловит и показывает модальный диалог**.

## 3. Компоненты (по восстановленным классам)

### 3.1 `MainWindow` (UI layer, было `QMainWindow`)

Главное окно приложения. Порождено из UI-описания (аналог `.ui`/дизайнера) — содержит
`centralwidget`, `menubar`, `statusbar`, кнопки **`start`** и **`reset`**.

Конструктор: `MainWindow(parent, cellSize:int, height:uint, width:uint)` — те же параметры,
что и у модели лабиринта; окно, по сути, прокси/владелец модели+вида.

Методы:
- `reset()` — сброс лабиринта к начальному состоянию (новая генерация или возврат визора
  на старт — не определяется однозначно по бинарнику).
- `slot()` — обработчик тика таймера (`QTimer::timeout`); на каждый вызов продвигает
  состояние лабиринта на один шаг.
- `paint_slot()` — запрашивает перерисовку виджета лабиринта после каждого шага.

Обнаруженная Qt-инфраструктура вокруг окна: `QTimer` (`start(int)`/`stop()`/`timeout()`),
`QGridLayout`, `QScrollArea` (виджет лабиринта, видимо, скроллируемый — актуально для
больших лабиринтов), `QTextBrowser` (вероятно, справка/статистика/лог), `QPushButton`
(`start`, `reset`), `QStatusBar`.

### 3.2 `Maze` (Domain + View, было `maze : QWidget`)

Сетка лабиринта: и модель, и её отрисовка совмещены в одном классе (типичная для маленьких
Qt-проектов, но при переносе **стоит разделить** — см. раздел 6).

Конструктор: `Maze(parent, cellSize:int, height:uint, width:uint)`.

Методы:
- `paintEvent(QPaintEvent*)` — отрисовка: `QPainter::drawLines` (стены клеток) +
  `QPainter::drawEllipse` (маркер текущей позиции/визора).
- `showMaze()` — публичная точка входа для (пере)отрисовки/показа состояния.
- **`gotoAndVisor(direction: byte)`** — ключевой метод домена: перемещает "визор" (текущую
  позицию) на один шаг в переданном направлении, обновляет внутреннее состояние (стены/
  посещённые клетки/счётчики).

**[инференция]** Ни в `MainWindow`, ни в `Maze` нет переопределения обработчика клавиатуры
(`keyPressEvent`). Это значит, что перемещение по лабиринту **не управляется игроком
напрямую с клавиатуры** — движение происходит по таймеру (см. `QTimer` + `slot()`), т.е.
это, скорее всего, **автоматическая пошаговая анимация прохождения** (авто-solver), а не
ручной геймплей. Направление на каждый шаг вычисляется где-то внутри `gotoAndVisor`/модели.

**[инференция]** Конкретный алгоритм генерации стен и алгоритм прохождения **не
восстанавливаются из символов бинарника** — шаблонные контейнеры (`std::stack`/`vector`/
`queue`), если использовались, инлайнятся компилятором и не оставляют отдельных символов.
То, что вся логика перемещения умещается в единственный метод с минимальной сигнатурой
(`gotoAndVisor(direction)`, без явного стека/очереди состояний), намекает на алгоритм с
малым объёмом состояния (например, правило одной руки / wall-follower), но это не
доказательство — при портировании выбор алгоритма нужно принять заново, ориентируясь на
`Steps count` / `States count` (см. ниже) как на желаемые метрики.

### 3.3 `MazeError` (было `mError`)

Простое доменное исключение с текстовым сообщением (конструктор принимает `std::string`).
Используется для сигнализации об ошибках конфигурации/состояния наверх, в UI-слой.

## 4. Поток управления (реконструкция)

```
main()
 └─ создать QApplication
 └─ прочитать config.txt
      ├─ ошибка парсинга/валидации → throw MazeError("...")
      │      └─ поймано в UI → QMessageBox: "Warning!" / "try again" / "Failure"
      └─ ok → cellSize, height, width
 └─ создать MainWindow(cellSize, height, width)
      └─ создать Maze(cellSize, height, width) как central/scroll-widget
      └─ сгенерировать лабиринт (стены), поставить визор на старт
 └─ MainWindow.show()

Нажатие "start":
 └─ QTimer.start(intervalMs)
      └─ на каждый timeout():
           MainWindow.slot()
             └─ direction = вычислить следующий шаг (алгоритм прохождения)
             └─ Maze.gotoAndVisor(direction)
                   ├─ обновить позицию визора
                   ├─ increment Steps count
                   ├─ (опционально) increment States count при посещении новой клетки
             └─ MainWindow.paint_slot() → Maze.update()/showMaze() → paintEvent()
      └─ если визор достиг выхода:
             QTimer.stop()
             показать диалог "Congratulations" / "You win!"
                с текстом "Steps count: N", "States count: M"
             кнопка "Close"

Нажатие "reset":
 └─ MainWindow.reset() → остановить таймер, пересоздать/сбросить Maze, перерисовать
```

## 6. Рекомендации по переносу в другую кодовую базу

Оригинал жёстко связывает модель и отрисовку в одном классе (`Maze : QWidget`) и завязан
на Qt (QPainter/QTimer/QMainWindow). Для переносимой архитектуры разделить на независимые
от фреймворка части:

```
config/
  MazeConfig { cellSize, height, width }
  loadConfig(path) -> MazeConfig | throws ConfigError

domain/
  Grid { width, height, walls[] }        // модель стен клетки (например, битовая маска N/E/S/W на клетку)
  MazeGenerator (interface)               // generate(width, height) -> Grid
  MazeSolver (interface)                  // step(Grid, currentPos) -> nextPos | done
  MazeSession {                           // объединяет Grid + текущую позицию + счётчики
    grid, visorPos, stepsCount, statesCount, visited: set
    step(solver) -> bool isFinished
    reset()
  }

ui/ (тонкий слой, заменяемый под любой UI-фреймворк)
  MainWindowView   — кнопки start/reset, statusbar, обработка событий таймера
  MazeView         — рендер Grid + позиции визора (аналог paintEvent)
  Dialogs          — Warning/try again/Failure, Congratulations/You win!
  AnimationLoop    — таймер, на каждый тик: session.step(solver); view.repaint()
```

Ключевое: `MazeGenerator` и `MazeSolver` — это **интерфейсы/стратегии**, конкретную
реализацию (DFS backtracker / Prim / Kruskal для генерации; wall-follower / BFS / DFS /
A* для прохождения) нужно выбрать явно на новой кодовой базе — из бинарника оригинала
эта деталь не восстанавливается. `MazeSession` хранит `stepsCount` (число шагов) и
`statesCount` (число посещённых уникальных клеток) — это два метрики, которые оригинал
показывает по завершении, их стоит сохранить как контракт, независимо от алгоритма.

`AnimationLoop` — пошаговая, управляемая таймером (не мгновенное решение с последующей
отрисовкой пути целиком) — сохранить как поведенческий контракт, если нужна визуальная
анимация прохождения как в оригинале.
