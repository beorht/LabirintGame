# ТЗ — Maze Quest (Браузерная игра-лабиринт)

**Версия:** 1.0
**Дата:** 18.04.2026
**Тип проекта:** Веб-приложение (игра)
**Платформа:** Браузер (Desktop + Mobile)

---

## 1. Общие сведения

### 1.1 Наименование проекта

Maze Quest — интерактивная образовательная платформа для программирования алгоритмов поиска пути. Игрок решает лабиринты, написав последовательность команд на JavaScript-подобном языке. Включает процедурную генерацию карт, систему препятствий, монет и многоуровневый прогресс.

### 1.2 Назначение системы

Maze Quest — это образовательная платформа для изучения алгоритмов и логического программирования. Игрок пишет последовательность команд на JavaScript-подобном синтаксисе для управления персонажем. Персонаж должен найти путь от стартовой точки A до финишной точки Б (обозначена флагом 🚩) и выполнить команду `personage.finish()`. По пути расставлены ловушки (штрафуют за шаги) и монеты (бонусы). Цель — решить головоломку за минимальное количество команд, шагов и времени.

### 1.3 Основания для разработки

- Запрос на казуальную браузерную игру с образовательным элементом (поиск пути, логика)
- Применимость как учебной платформы для демонстрации алгоритмов поиска пути
- Реализация без установки сторонних плагинов и фреймворков

## 2. Цели и задачи

### 2.1 Цели

1. Реализовать полноценную браузерную игру без внешних зависимостей.
2. Обеспечить процедурную генерацию уникального лабиринта при каждом запуске.
3. Предоставить систему нарастающей сложности.
4. Внедрить алгоритм BFS для режимов подсказки и решения.
5. Поддержать управление с клавиатуры, мыши и тач-устройств.

### 2.2 Задачи разработки

- Разработать движок генерации лабиринта (Recursive Backtracker).
- Реализовать игровую логику: движение, коллизии, ловушки, монеты, победа.
- Реализовать алгоритм BFS для поиска кратчайшего пути.
- Создать HUD с отображением шагов, времени и уровня.
- Реализовать адаптивный интерфейс для мобильных устройств.
- Обеспечить систему прогрессии уровней (1–5+).

## 3. Требования к функциональности

### 3.1 Игровое поле

Поле — прямоугольная сетка клеток, базовый размер 14×14.

| Тип клетки | Обозначение | Описание |
|---|---|---|
| Стена | ■ тёмный | Непроходимая клетка |
| Путь | □ светлый | Проходимая клетка |
| Старт | A зелёный | Начальная позиция игрока |
| Финиш | 🚩 синий флаг | Целевая точка (завершение маршрута) |
| Ловушка | ✕ красный | Препятствие, штраф +5 шагов |
| Монета | ★ золотой | Бонус, собирается при наступлении |

### 3.2 Генерация лабиринта

- Алгоритм: Recursive Backtracker (DFS с обходом стен).
- Гарантируется наличие хотя бы одного пути от A до Б.
- Ловушки и монеты размещаются случайно на проходимых клетках после генерации.
- Количество ловушек: `4 + (уровень × 2)`. Монет: 5 на каждом уровне.
- При каждом старте новой игры генерируется новый уникальный лабиринт.

### 3.3 Управление персонажем (Код-ориентированный подход)

Управление персонажем осуществляется путём написания команд в коде. Игрок пишет последовательность команд, которые затем выполняются пошагово.

**Доступные команды:**

| Команда | Действие |
|---|---|
| `personage.up()` | Движение персонажа вверх на одну клетку |
| `personage.down()` | Движение персонажа вниз на одну клетку |
| `personage.right()` | Движение персонажа вправо на одну клетку |
| `personage.left()` | Движение персонажа влево на одну клетку |
| `personage.finish()` | Завершить прохождение лабиринта (если персонаж находится на финише) |

**Пример кода:**
```javascript
personage.down();
personage.left();
personage.left();
personage.right();
personage.up();
personage.finish();
```

**Интерфейс:**
- Левая часть: Игровое поле с лабиринтом и персонажем
- Правая часть: Редактор кода для ввода команд
- Кнопка "Выполнить" (Run): Запускает пошаговое выполнение команд
- Визуализация: Персонаж последовательно выполняет каждую команду с анимацией

### 3.4 Игровые механики

**Выполнение команд:**
- Команды выполняются последовательно при нажатии кнопки "Выполнить".
- Между каждой командой пауза ~500мс для визуализации движения.
- Если команда невалидна или персонаж не может выполнить движение (стена/граница), отображается ошибка и программа останавливается.
- Номер текущей выполняемой команды подсвечивается в редакторе кода.

**Ловушки:**
- При наступлении счётчик шагов увеличивается на 5.
- После активации ловушка исчезает (клетка становится проходимой).
- Игроку отображается уведомление.

**Монеты:**
- При наступлении счётчик монет увеличивается на 1.
- Монета исчезает после подбора.
- Итоговое количество монет отображается в экране победы.

**Победа:**
- Засчитывается при вызове команды `personage.finish()` когда персонаж находится на финишной клетке 🚩.
- Отображается итоговая статистика: шаги, время, монеты, количество команд.
- Уровень сложности увеличивается на 1 (максимум — 5).

### 3.5 Система подсказок

| Функция | Описание |
|---|---|
| Подсказка 💡 | Генерирует и вставляет в редактор кода следующие 5 команд оптимального пути от позиции игрока |
| Решение 🗺 | Генерирует и вставляет в редактор полный оптимальный набор команд до финиша с вызовом `personage.finish()` |
| Алгоритм | BFS — гарантирует кратчайший путь, команды отображаются в правильной последовательности |
| Вставка кода | Подсказки добавляются в конец кода редактора, может быть отредактировано перед выполнением |

### 3.6 HUD

- Счётчик шагов — обновляется при каждом движении.
- Таймер — отсчёт секунд с начала игры, останавливается при победе.
- Уровень — текущий номер уровня сложности.
- Счётчик монет — отображается на холсте при наличии подобранных монет.

### 5.4 Алгоритмы

**Генерация лабиринта — Recursive Backtracker:**
Алгоритм DFS. Начинает с клетки (1,1), рекурсивно посещает соседей через клетку, убирая стены. Гарантирует связный лабиринт с единственным путём между любыми двумя точками.

**Поиск пути — BFS (Breadth-First Search):**
Обход в ширину от позиции игрока до финиша. Гарантирует кратчайший путь. Используется для режимов «Подсказка» и «Решение». Сложность: O(V + E).

## 8. Критерии приёмки

### 8.1 Функциональные

1. Лабиринт генерируется корректно: путь от A до Б всегда существует.
2. Персонаж не проходит сквозь стены.
3. Ловушки наносят штраф и исчезают после активации.
4. Монеты подбираются и учитываются в итоговой статистике.
5. Подсказка показывает не более 5 ближайших шагов оптимального пути.
6. Режим решения показывает полный кратчайший маршрут до финиша.
7. После победы уровень увеличивается, генерируется новый лабиринт.

### 8.2 Нефункциональные

1. Страница загружается менее чем за 2 секунды на 3G.
2. Игра работает без ошибок в Chrome, Firefox, Safari, Edge.
3. Управление работает с клавиатуры, мыши и тач-экрана.
4. Интерфейс корректно отображается при ширине экрана от 320px.
5. Поддерживается светлая и тёмная тема.
